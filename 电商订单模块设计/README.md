订单模块的设计稿已经用 Design 类型建好，画布上有两张画板：

- **主流程**：正向链路分六步，依次是提交订单、库存预占、支付、发货、确认收货、完成结算，每步标出对应的订单状态。下方是四条异常和逆向分支：取消订单、支付失败、仅退款、退货退款。
- **状态机与关键设计**：左侧是 8 条状态流转规则，列出当前状态、目标状态、触发条件和副作用。右侧是五个设计要点：状态机约束加乐观锁、幂等、库存三段式（预占、确认、释放）、分布式一致性（事务消息加 Saga）、审计与对账。

我做了几个假设：支付超时按 30 分钟，自动确认收货和售后期都按 7 天，这些数值可以按业务改。为了让首版快速完成，我只做了这两张纯文字画板，没有画泳道图、时序图，也没有补充数据库表结构或接口定义。
